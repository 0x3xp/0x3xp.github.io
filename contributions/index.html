Memory leak of tftp_server_name in slirp_cleanup()

Oct 18, 2026 C · Memory Safety
Finding

tftp_server_name is heap-allocated during initialization but never freed in the cleanup path slirp_cleanup(), causing a persistent memory leak on every instance teardown in QEMU and other consumers of libslirp.

Buffer underflow in tftp_handle_rrq() when handling empty filename

Oct 2026 C · Memory Safety
Finding

When a TFTP read request (RRQ) is received with an empty filename, tftp_handle_rrq() performs pointer arithmetic that results in a buffer underflow — reading memory before the start of the allocated buffer. This can cause undefined behavior and potential information exposure.

Protocol type mismatch in icmp6_receive(): IPv4 ICMP_UNREACH emitted as ICMPv6

Oct 2026 C · Protocol
Finding

In icmp6_receive(), an IPv4 ICMP_UNREACH error is incorrectly emitted using the ICMPv6 send path. This protocol type mismatch causes malformed packets to be constructed and sent, breaking network error signaling for IPv4 unreachable conditions handled through the IPv6 receive path.

Double socket descriptor leak in fork_exec() on argument parsing failure

Oct 2026 C · Resource Management
Finding

In fork_exec(), when argument parsing fails after a socket pair has already been created, both socket file descriptors are returned without being closed. This causes a double file descriptor leak on every failed invocation, gradually exhausting the process file descriptor table.

Merged Resource Leak

Socket heap memory & buffer leak in slirp_state_load() on deserialization or validation failure

Oct 2026 C · Resource Management
Finding

In slirp_state_load(), if deserialization or validation of a socket fails partway through, the already-allocated socket structure and its associated send/receive buffers are not freed before returning an error. This results in heap memory and buffer leaks on every failed state restore operation.

Merged Concurrency

Non-reentrant static variable in tcp_emu() corrupts protocol parser across sessions

Oct 2026 C · Concurrency
Finding

tcp_emu() uses a static local variable to maintain parser state across calls. Because static local variables are shared across all call sites in a process, concurrent or interleaved sessions corrupt each other's protocol parser state — causing silent protocol parsing failures and undefined behavior in multi-instance libslirp environments.

Merged Info Disclosure

Echo reply length desynchronization in icmp_receive() and icmp6_receive()

Oct 2026 C · Protocol
Finding

In both icmp_receive() and icmp6_receive(), the length field of echo reply packets is not correctly synchronized with the actual payload size. This desynchronization causes malformed ICMP echo replies to be emitted, which can expose uninitialized buffer contents to the network peer — a potential information disclosure condition.

About libslirp

freedesktop.org

libslirp is the user-mode TCP/IP networking stack used by QEMU, VirtualBox, and other major virtualization and emulation platforms. It implements a full network stack in user space, translating guest network traffic without requiring elevated OS privileges. Issues in libslirp directly affect the reliability and security of any system running virtual machines through QEMU.

All contributions above were identified through manual source-level code review, reported upstream with reproduction context and fix proposals, and subsequently merged into the project.
